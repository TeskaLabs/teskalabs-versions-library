Microlink backend and WebUI are excluded from this release train. Their initial customer deployment is through the separate AI VM. The supplied `llm_microlink_webui` final tag `v26.41` is intentionally not included.

## Breaking Changes

- **ASAB Remote Control:** the default model layout changes and deprecated TLS ciphers are removed from NGINX configuration. Review custom site models and clients relying on those ciphers before deployment.
- **LMIO Common Library:** Windows status fields move from `we.status_name` to `we.failure_code`; client IP addresses move from `host.ip` to `source.ip`. NPS policy fields replace `we.proxy.policy_name`, and `lmio.database.name` replaces `database.name`. Windows correlations now group by `host.hostname`. The default archive warm-retention period changes from three months to one month. Review custom mappings, queries, dashboards, correlations, and retention profiles before upgrading.
- **LMIO Alerts:** notification configuration moves from `model.yaml` into Library and uses a new format. Instant notifications now run when a ticket is created, updated, or activated. APIs require authorization. `WorkflowStatusReason` and SLA timeline item payloads change.
- **LMIO Elman:** datasources move to Library; event-lane detail storage in ZooKeeper is removed. Schemas load from the global Library with extensions through `LibrarySchemaService`. Site models are read from the global layer only.
- **LMIO Chart:** datasources are read from Library rather than ZooKeeper. Loading Elman-managed datasources requires `lmio-elman:v26.25-alpha` or higher; the supplied Elman tag is `v26.37.02`.
- **BitSwan Query:** the technical user for the Pyppeteer datasource is removed in favor of internal authentication. URL-fragment extraction behavior changes.
- **WebUI:** release v26.13 requires compatible backend schema endpoints and Alerts APIs. The supplied changelog specifies ASAB WebUI Components >= `27.8.0`, ASAB WebUI Shell >= `27.4.0`, ASAB Library >= `v26.37-alpha3` for promote/demote, and the Chart/Receiver/Remote Control/Governator minimums documented in the WebUI changelog below. Confirm the deployed WebUI dependencies satisfy these requirements.
- **Microlink:** the backend and `llm_microlink_webui` version entries present in beta10 are removed from this release.

## Upgrade Procedure v26.12 → v26.37

These steps consolidate the supplied changelog requirements. Service-owner migration details still marked pending must be resolved before customer rollout. For systems already running a v26.37 beta, check whether each migration has already been completed.

### Before the upgrade

1. Resolve the missing release information above. Verify the selected images and WebUI distributions are available before deploying.
2. Back up the current site model and relevant Library configuration. Review temporary service-version and configuration overrides in `/Site/model.yaml`; remove obsolete overrides only after reviewing their purpose. A local `version` pin overrides the selected application release.
3. Prepare Alerts notification migration from model configuration to Library using the [notification migration instructions](https://ndocs.teskalabs.com/logman.io/alerts/notifications_v2637/#enable-notification-channels). Check notification channel formats and credentials. Review `/Alerts/Workflow/` and the global default in `alert.yaml` using the [workflow documentation](https://ndocs.teskalabs.com/logman.io/alerts/workflow/#default).
4. Review whether Alerts compression should be enabled; it is disabled by default in the supplied changelog. Follow the [compression configuration instructions](https://ndocs.teskalabs.com/logman.io/alerts/compression/#enable-compression). Preserve the site's intended setting rather than assuming it is enabled.
5. Review Elman/Chart datasource migration from ZooKeeper to Library and keep schemas on the global layer with `/Schemas/Extensions/`. Confirm the selected libraries provide `LibrarySchemaService`. Obtain service-owner migration steps where required; no automatic migration command was supplied.
6. For Chart running on multiple nodes, configure the same `LMIO_CHART_DOWNLOAD_SECRET_KEY` (`[download] secret_key`) on every instance so signed CSV/Parquet downloads work across replicas. Store the value through the site's secret mechanism.
7. Review BitSwan Query's Pyppeteer datasource integration for removal of the technical user and use of internal authentication. Test report URLs containing fragments.
8. Disable the Microlink MFE route in `/Site/LogMan.io/WebApps/LogMan.io WebUI.yaml` in the deployment Library. This descriptor is absent from this versions repository and must be changed in the Library that owns it:

    ```yaml
    # /llm_microlink_webui: llm_microlink_webui # LLM not used in LogMan.io installations
    ```

    Review any site-level Microlink service and WebUI overrides separately; excluding version entries does not by itself update a site's model or its WebUI descriptor. Keep the separate AI VM configuration outside this release train.
9. Review the Elasticsearch/Kibana and MongoDB version changes relative to the installed v26.12 patch. The selected versions are Elasticsearch/Kibana `8.19.12` and MongoDB `8.0.20`. Follow the applicable supported data migration procedures; this release note does not supply a database migration runbook.

10. Review Common Library schema and parser changes in custom content: replace Windows status references with `we.failure_code`, use `source.ip` for the client address, and use `host.hostname` for the affected Windows correlation grouping. Replace `we.proxy.policy_name` with the applicable `we.connection_request_policy.name` / `we.network_policy.name`, and `database.name` with `lmio.database.name`. Check custom data types against `network.packets` changing to `si64`.
11. Review notification template references: `Ticket Created.md` becomes `Ticket Overview.md`, and `Ticket Updated.md` becomes `Ticket Activity Update.md` in the supplied Email, Slack, Push, and SMS changes. Verify custom notification settings reference the intended files.
12. Review archive retention profiles before applying the Common Library update: the default warm phase shortens from three months to one month. Confirm this matches the site's retention requirements.

13. Check custom model compatibility with Remote Control v26.43's changed default layout, and test client compatibility with the reduced NGINX TLS cipher configuration. Review nightly housekeeping procedures: changes are applied to one node per night. Confirm any custom Docker/Podman socket path uses the intended `DOCKER_SOCKET` / Docker socket settings.
14. Deploy the WebUI patch together with SeaCat Auth `v26.15.01` or higher. SeaCat Admin WebUI `v26.13.01` requires this backend version for assigning a tenant when creating credentials.

### Upgrade

1. Select the paired release in `/Site/model.yaml`:

    ```yaml
    applications:
      - name: ASAB Maestro
        version: v26.37
      - name: LogMan.io
        version: v26.37
    ```

2. Generate and inspect the deployment plan. Confirm both applications resolve to the paired release, service tags match the version files, obsolete local pins are gone, and instance placement remains correct. Where Alerts HA is intended, verify one instance on each intended node. Elman supports HA, but confirm the site's placement explicitly.
3. Following the existing release procedure, Apply to cluster nodes one at a time. Wait for pulls and startup to succeed before proceeding to the next node. Stop and resolve missing-image or startup errors before continuing.
4. After every node has started successfully, Apply again one node at a time to refresh libraries, as in the previous release procedure. Wait for services to become ready again.

### After the upgrade

1. Confirm the deployed images and WebUI versions match the release files and the services are healthy on their intended nodes.
2. Verify datasource loading, schema extensions, event lanes, parser reloads, collection, ingestion, and asset/activity updates. If Elman HA is configured, verify leader election and read-only follower API behavior.
3. Verify Alerts creation, updates, activation, suppression, closure reasons, notification delivery, and scheduled notifications. Check compression behavior against the chosen configuration and review timeline rendering in WebUI.
4. Test Chart CSV/Parquet/JSON exports, including multi-node downloads, numeric/boolean group-by fields, and malformed queries. Confirm all Chart instances use the shared download secret.
5. Verify Receiver stream discovery and replay, including open partitions and cleanup. Review existing streams for missing `define.type: jizera/stream`; the Receiver changelog supplies `tools/fix_stream_definitions.py`. Follow service-owner instructions before using that repair tool.
6. Test Library schema validation, batch saves, import/export, promote/demote, search, and scoped access. Test SeaCat LDAP login, authorization, audit logs, and report rendering through BitSwan Query/Pyppeteer.
7. Confirm the Microlink MFE route remains disabled in the LogMan.io deployment and that the separate AI VM works independently.

8. Verify parsed Windows client/host addresses, failure codes, NPS policy fields, database names, `network.packets` types, and affected Windows correlations using representative events. Check custom dashboards and queries against the new mappings.
9. Confirm the effective archive retention profile, notification template paths, and the default `/Filters/Default.json` behave as intended after the Library refresh.

10. Test the configured Collector inputs and forwarding paths, especially WEC/WEF, Smart TCP reload and framing, CommLink syncback, and Elasticsearch pagination where used. Check auto-generated server certificate SANs and renewal, and any configured line delimiters or Beats `message_only` setting.

11. If multiple Franz instances are configured, verify that ZooKeeper leader election selects one active instance, followers remain idle, and failover works as intended.

12. Verify the Client create screen and tenant selection when creating credentials in SeaCat Admin. Check Remote Control instance commands, procedures and housekeeping, Governator command acknowledgments, node metrics, logs export, and cluster datetime consistency as applicable to the site.

13. Verify Ededup starts with the generated `[web]` and `[frame]` listen addresses, advertises its web and frame ports correctly, and processes deduplication traffic. Check ASAB Config startup and configuration-watch updates after its runtime/Kazoo upgrade.
